# Caesar — website rebuild

A rebuild of [caesar.co.il](https://www.caesar.co.il/) for **קיסר ניהול נכסים**
(Caesar Property Management) as a scroll-driven marketing site. Hebrew, full RTL.

Next.js 16 (App Router) · TypeScript · Tailwind v4 · GSAP ScrollTrigger · Lenis · Macaly Cloud.

Work is in progress; see `PLAN.md` for what is done and what is blocked.

## Getting started

```bash
npm install          # Node 22+
npm run dev          # http://localhost:3000
```

Copy `.env.example` to `.env.local` for local config. **Never commit a `.env`** —
`.gitignore` covers `.env*` except the example.

## The content layer

`content/pages.json` is the only source of routes, copy, metadata and the sitemap.

- **Types are generated, not hand-written.** `scripts/gen-content-types.ts` compiles
  `contracts/content.schema.json` into `lib/content.types.ts` with
  `json-schema-to-typescript`. The schema is the single source of truth; the generated
  file is committed but regenerated by `prebuild`, so it cannot drift. Do not edit it —
  edit the schema.
- **Validation is Ajv, against the same schema file**, in `lib/content.ts`, at module
  scope. Every page imports it, so a schema error fails `next build`. JSON Schema
  conditionals (`if`/`then`, e.g. "a video must have a poster") cannot be expressed in
  static TypeScript, so Ajv is the complete half of the contract and the generated types
  are the structural half.
- **Cross-field rules the schema cannot express** are also checked there: duplicate slugs,
  duplicate section ids, a motion preset used on a section type
  `contracts/motion.spec.md` does not allow it on, more than two `pin-reveal` per page,
  more than one `horizontal-scroll` per page, and a missing `/` page.

### The two build gates

| Gate | When | How to satisfy it |
| --- | --- | --- |
| Schema | Always | Fix `content/pages.json`. |
| Placeholder | Production builds only | No media may carry `origin: "placeholder"`. |

The placeholder gate is a gate on **producing** a build, not on serving one — `next build`
and `next start` both run with `NODE_ENV=production`, so `next.config.ts` stamps
`CONTENT_GATE=production` when Next reports the production-build phase, and
`npm run build` sets it too. A server running an already-approved build never 500s
because of it.

While assets are pending, build with `npm run build:draft`. Once every asset has a real
`origin` of `kling` or `original-site`, plain `npm run build` passes and the escape hatch
is no longer needed. **The deploy pipeline must use `npm run build`, never
`build:draft`.**

## Motion

`contracts/motion.spec.md` is binding. All five presets plus `none` are implemented in
`hooks/useScrollAnimation.ts`.

```tsx
const { ref, mode } = useScrollAnimation<HTMLElement>({ preset: section.motion });

<section ref={ref}>
  <h2 data-motion-heading>{section.heading}</h2>
  <p data-animate>{section.body}</p>
</section>
```

- **The hook owns trigger creation and cleanup.** Nothing else calls
  `ScrollTrigger.create` (motion.spec rule 5). Teardown is `gsap.matchMedia().revert()`,
  which kills every tween and trigger it made.
- **`prefers-reduced-motion` is handled centrally, in the hook.** A section asking for
  `pin-reveal` under reduced motion gets the static path from the hook. Components must
  not write their own branch.
- **Nothing is hidden by CSS.** Initial hidden states are set by GSAP, in a layout effect
  (so before paint), on the animated path only. A no-JS or reduced-motion render is
  therefore complete by construction, not by a fallback.
- The hook stamps `data-motion="{preset}"` and `data-motion-mode="animated|static"` on the
  section root. The layout each preset needs lives in `app/globals.css` keyed off those.

### Markup hooks a section supplies

| Attribute | Used by | For |
| --- | --- | --- |
| `data-animate` | `fade-up`, `pin-reveal` | Children that stagger in. |
| `data-motion-heading` | `text-split` | The heading to split. Lines only — never characters (Hebrew shaping). |
| `data-motion-parallax` | `parallax-slow` | The layer that moves slower than the page. |
| `data-motion-viewport` / `data-motion-track` | `horizontal-scroll` | The clipping box and the sliding row. |
| `data-motion-step` | `pin-reveal` | The states advanced while pinned. Put them in a `.motion-steps` grid. |

`--motion-progress` (0–1) is written on the section root for every scrubbed preset, in
both modes. `.motion-progress` in `globals.css` renders it as a bar — `horizontal-scroll`
must show one (motion.spec rule 1) and it keeps working when the preset degrades to a
native overflow row.

RTL is handled: `horizontal-scroll` advances right-to-left when the computed direction is
`rtl`, and the CSS uses logical properties throughout. Use Tailwind's logical utilities
(`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `text-end`) — never
`left`/`right`.

## Fonts

`@fontsource-variable/heebo`, self-hosted from npm and imported in `app/layout.tsx`.
`next/font/google` is not usable here — the build environment has no route to
`fonts.googleapis.com` — and a webfont that only exists at a CDN is a webfont that
sometimes is not there. The fallback stack in `app/globals.css` is real Hebrew faces, not
just `sans-serif`.

The OG renderer uses the **static** cuts (`@fontsource/heebo`) baked to base64, because
satori reads neither WOFF2 nor variable fonts. It also pre-reorders text to visual order
(`lib/og-bidi.ts`) because satori does not implement the bidi algorithm.

## Media

`public/media/{section-id}/{variant}.{ext}`, per `contracts/assets.md`. Drop originals in,
then `npm run media:optimize`. Images become `.webp` + `.avif` (plus `.jpg` for the hero);
videos become `.mp4` + `.webm` with a `{variant}-poster.webp` from frame 0.

The script needs a full ffmpeg. `ffmpeg-static` is a devDependency and is used by default;
`FFMPEG_PATH` overrides it. The ffmpeg Playwright ships is a stripped build with no
libx264 and no mp4 muxer — the script detects that and says so rather than failing
cryptically.

## Contact form

`POST /api/contact` with `{ name, email, phone?, subject?, message, pageSlug?, company? }`.
`company` is a honeypot; leave it empty. Responses: `200 {ok:true}`, `422` with per-field
Hebrew errors, `429` when throttled, `502` on a delivery failure.

Delivery is env-driven (`.env.example`): `EMAIL_PROVIDER=console` (default, logs only, no
network), `resend` (needs `EMAIL_API_KEY`, `CONTACT_TO_EMAIL`, `CONTACT_FROM_EMAIL`), or
`smtp` (reserved, returns 501). Add a provider by implementing a `Sender` in
`lib/email.ts`.

## Screenshots

```bash
npm run build:draft && npm run shots
```

Writes `screenshots/{project}/{slug}.png` (gitignored) for six projects: 375, 768 and 1440,
each in a normal and a reduced-motion pass. The suite also asserts the reduced-motion
contract — every section in `static` mode, nothing left transparent — and smoke-tests the
OG and contact routes.

Chromium is **pre-installed**; `PLAYWRIGHT_BROWSERS_PATH` is already set and
`playwright.config.ts` resolves the binary explicitly. **Never run `playwright install`.**
